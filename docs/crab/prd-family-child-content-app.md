# 家庭内部儿童内容浏览工具 PRD

## 1. 文档信息
- 文档名称：家庭内部儿童内容浏览工具 PRD
- 版本：v0.2
- 日期：2026-05-26
- 状态：草案

## 2. 产品定位
这是一个面向家庭内部使用的儿童内容浏览工具，不做开放内容平台，不做社区，不做公开分发。

产品目标是让家长能够快速发现优质内容并安全地投喂给孩子，让孩子只在受控的专属 App 内浏览，不需要直接使用抖音等原始内容 App。

一句话定义：

> 家长发现内容，一键送进孩子专属 App，孩子只在安全壳里看。

## 3. 背景与问题
当前家长在给孩子筛选科普、知识、见闻类内容时，主要存在以下问题：

1. 优质内容分散在抖音、X、微信视频号、普通网页、图文、音频等不同来源。
2. 家长转发内容给孩子的路径不顺手，经常需要跨 App 操作。
3. 孩子直接打开原始内容平台，容易进入 feed、评论区、外链和其他不受控内容。
4. 家长真正需要的不是一个成熟的儿童内容平台，而是一个家庭内部可控、足够轻、能持续使用的内容中转工具。

## 4. 目标用户
### 4.1 核心用户
- 家长：负责发现、筛选、投喂内容。
- 孩子：大约 10 岁左右，使用专属 App 浏览内容。

### 4.2 使用场景
- 家长在抖音看到适合孩子的视频，希望不让孩子打开抖音也能观看。
- 家长在网页、文章、音频中发现适合孩子的内容，希望快速推送到孩子端。
- 孩子在限定时间和限定容器中浏览家长批准的内容。

## 5. 产品目标
### 5.1 MVP 目标
1. 支持家长快速导入内容链接。
2. 支持孩子端以安全壳方式浏览内容。
3. 在抖音内容场景下，优先通过 WebView 播放单条内容，不进入抖音主 feed。
4. 当 WebView 播放不稳定或不可用时，自动切换到私有视频兜底方案。

### 5.2 非目标
以下内容不在当前阶段范围内：
- 开放式儿童内容社区
- 孩子端全网搜索
- 评论、点赞、关注、分享社交关系
- 无限推荐流
- 面向陌生用户的内容运营体系
- 要求家长手动上传视频文件作为常规流程

### 5.3 账号与家庭绑定
MVP 采用极简的"配对码"机制建立家庭关系，避免引入复杂的注册登录流程：

1. 家长端生成一个家庭配对码。
2. 孩子端输入配对码完成绑定。
3. 一个家庭支持绑定多个孩子，家长可以在投喂时选择目标孩子。
4. 同一个家庭的家长端和孩子端共享内容池（但孩子只能看到分配给自己的内容）。

后续可扩展：
- 多家长（如爸爸和妈妈共同管理）
- 跨设备同步（家长换手机后恢复绑定）

## 6. 核心原则
1. **导入要快**：家长导入动作应尽可能控制在 1~2 步内。
2. **孩子出不去**：孩子只能在受控容器内浏览，不应被带回原始平台。
3. **兜底自动化**：播放失败时，系统应优先自动切换兜底路径，而不是把额外操作转嫁给家长。
4. **先闭环，再扩展**：先验证"家长持续投喂、孩子持续消费"的闭环，再扩内容源和功能。

## 7. 产品方案概览
建议采用"一个后台 + 两个前端角色"的结构：

### 7.1 家长端
建议先使用一个极简分享壳，优先保证它能出现在系统分享面板中。

首期职责：
- 接收外部 App 分享进来的内容
- 展示最小预览
- 选择发送给孩子

首期不要求承担完整内容管理台职责。

### 7.2 孩子端
使用独立 App，负责：
- 内容浏览
- 内容播放
- 收藏
- 最近观看

孩子端不承担内容导入与复杂管理功能。

## 8. 核心用户流程

### 8.1 家长投喂流程
1. 家长在外部平台发现内容。
2. 通过"系统分享"或"复制链接"导入到工具。
3. 系统识别内容并生成内容卡片。
4. 家长选择发送给哪个孩子。
5. 孩子端收到内容并展示在列表中。

### 8.2 孩子浏览流程
1. 孩子打开专属 App。
2. 进入"今日推荐"或"分类"。
3. 点击内容卡片。
4. 在受控容器内播放或阅读。
5. 可以收藏或继续浏览其他内容。

## 9. 功能需求

## 9.1 家长端功能
### 9.1.1 内容导入
支持以下入口：
- 系统分享导入：在外部 App 中通过系统分享面板发送到家长端
- 复制链接识别：家长在外部 App 复制链接后，打开家长端自动识别剪贴板中的链接
- 手动粘贴链接：家长在家长端内手动粘贴链接

首期重点支持：
- 抖音链接
- X 链接
- 微信视频号链接
- 普通网页链接

后续可扩展：
- 音频链接
- 图文内容
- 本地视频资源

**链接去重**：
- 同一链接重复导入时，系统识别为已有内容并提示家长，避免重复处理。
- 对于同一视频的多条不同链接（如短链展开后相同），系统在标准化 URL 后进行去重。

### 9.1.2 内容管理
- 查看已导入内容列表
- 查看处理状态：pending / ready / failed
- 为内容打标签
- 选择发送给哪个孩子
- 删除已导入内容

### 9.1.3 内容分发
- 将单条内容发送给指定孩子
- 可重复发送历史内容
- 支持同时发送给多个孩子

### 9.1.4 内容生命周期管理
- **撤回**：家长可以将已发送给孩子的内容撤下，撤下后孩子端不再显示该内容。
- **重新上线**：撤回的内容可以重新发送。
- **自动清理**：已发送超过 30 天且孩子未打开过的内容，系统可提示家长是否清理。

## 9.2 孩子端功能
### 9.2.1 页面结构
首期仅保留 4 个核心页面：
- 今日推荐
- 分类
- 我的收藏
- 最近看过

### 9.2.2 浏览与播放
- 卡片流展示
- 大封面、少文字
- 单击进入内容详情/播放页
- 支持视频、文章、音频等不同播放模式

### 9.2.3 家长控制
家长可以为每个孩子设置以下限制：

- **每日使用时长限制**：孩子端累计使用超过设定时长后，当天无法继续使用。MVP 建议默认 60 分钟/天，家长可调整。
- **内容新鲜度优先**：新投喂的内容排在前面，超过设定天数未查看的内容自动下沉或隐藏。

控制策略由家长端设置，孩子端执行。孩子端在接近限额时（如剩余 5 分钟）进行友好提示，超时后展示提示页。

后续可扩展：
- 每日内容数量限制
- 按内容来源/分类的限制
- 指定可用时段（如仅允许 19:00-21:00）

### 9.2.4 受控体验
- 禁止跳转外部 App
- 禁止进入抖音 feed
- 禁止外部搜索
- 禁止评论区/社交区扩散
- 限制 WebView 内的非目标跳转

## 10. 抖音内容专项策略
这是当前产品讨论中的关键结论。

### 10.1 主策略
**WebView 作为首选播放方式。**

目标：
- 在 App 内打开单条抖音内容
- 尽量不跳转到抖音 App
- 不进入抖音首页或推荐 feed
- 尽量保持孩子在受控环境中观看

### 10.2 兜底策略
**导出为私有视频作为兜底方式。**

要求：
- 不把"手动上传视频"作为标准用户流程
- 应尽可能由系统完成私有化保存、导入或转存
- 对家长来说仍然是低摩擦、接近一键的体验

### 10.3 策略说明
该策略优先考虑家庭内部使用场景下的可用性与低摩擦，而不是做平台级的完美集成。

## 12. 技术与实现约束
### 12.1 平台建议
如果可选，优先 Android 平板作为孩子设备，因为在"安全壳"和系统层限制能力上通常更友好。

如果家庭主要使用 iPhone/iPad，也可实现，但更依赖系统提供的家长控制能力以及 App 内的严格限制。

### 12.2 容器要求
孩子端需要一个受限浏览器/播放器容器，用于：
- 拦截深链
- 阻断跳转到外部 App
- 控制 WebView 页面跳转
- 保证孩子停留在受控体验内

## 13. MVP 范围
MVP 只打透最小闭环：

1. 家庭配对码绑定（家长端 + 孩子端）
2. 家长端导入抖音链接
3. 后台生成内容记录
4. 孩子端展示卡片列表
5. 单条内容 WebView 播放
6. 禁止跳出 App
7. 播放失败时支持私有视频兜底
8. 家长可设置每日使用时长限制

## 14. 边界与异常场景

### 14.1 已处理
- **重复导入**：系统对 URL 标准化后去重，提示家长"该内容已存在"。
- **失效链接**：后台解析链接失败时，标记为 `failed` 状态，通知家长该内容不可用。
- **撤回内容**：家长撤回后，孩子端刷新列表后该内容消失；如果孩子正在播放被撤回的内容，播放完成后不再出现在列表中。

### 14.2 MVP 暂不处理（已知限制）
- **离线场景**：孩子端无网络时无法加载内容列表和播放，MVP 不提供离线缓存。
- **被删除内容**：抖音原内容被作者删除后，已导入的记录仍存在但 WebView 播放会失败，触发兜底路径或标记为不可用。
- **多家长协作**：首期不支持多个家长共同管理同一家庭。

## 15. 后续迭代方向
### Phase 1：验证闭环
验证家长是否愿意持续投喂、孩子是否愿意在专属壳中消费内容。

### Phase 2：增强兜底
- WebView 播放失败检测
- 私有视频版本生成
- 双播放策略
- 无感切换

### Phase 3：扩展内容类型
- 网页科普文章
- 音频
- 图文卡片
- 系列专题

## 16. 成功判断标准
MVP 阶段建议关注以下指标，并设定验证目标：

| 指标 | 验证目标 |
|------|----------|
| 家长从发现到完成投喂的操作步骤 | ≤ 2 步 |
| 导入到孩子端可见的延迟 | < 30 秒 |
| WebView 路径播放成功率 | > 70% |
| 兜底路径可用性 | 兜底触发后成功切换率 > 90% |
| 孩子端单次使用时长 | 平均 20-40 分钟（非强制，作为参考） |
| 孩子端每周重复打开天数 | ≥ 3 天（验证粘性） |
| 家长每周导入次数 | ≥ 3 次（验证持续投喂意愿） |

以上目标为方向性参考，实际值需在 MVP 上线后根据数据校准。

## 17. 风险点
1. 抖音 WebView 播放稳定性存在不确定性。
2. 深链、页面跳转、平台策略变化可能影响可控性。
3. 私有视频兜底的自动化实现存在技术边界。
4. 若家长导入链路不够顺手，工具会失去持续使用价值。
5. 配对码绑定机制虽简单，但如果孩子端设备更换频繁，需要支持重新绑定。

## 18. 当前结论
当前阶段，这个产品应被视为：
- 一个家庭内容路由器
- 一个儿童安全播放壳
- 一个家长审核后的内容收件箱

而不是一个完整的儿童内容平台。
